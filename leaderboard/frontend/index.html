Your matching engine needs to be compiled into a single Linux x86-64 binary that listens on port 8080 and exposes the REST endpoints below. The platform will containerise it, run a bot fleet against it, and score it automatically. No Docker knowledge needed — just compile and upload.

① Required API contract — your binary must expose these endpoints
EndpointMethodRequest bodyExpected response
POST /orderPOST {"bot_id":1,"type":"limit","side":"buy","price":100.5,"quantity":10} {"order_id":"abc123","status":"accepted"}
DELETE /order/:idDELETE — {"status":"cancelled"} or {"status":"not_found"}
GET /orderbookGET — {"bids":[...],"asks":[...]} — used as health check on startup
Logging convention (optional but recommended): print ORDER: <id> and FILL: <id> to stdout for each accepted order and fill. The platform uses these to catch phantom fills (more fills than orders), which counts against your correctness score.
② Compile command — pick your language
Install cross-compiler (once, on macOS or Windows)
# macOS brew install filosottile/musl-cross/musl-cross # Ubuntu / WSL — already targets Linux, skip this step
Compile — statically linked, no libc dependencies
# On Linux / WSL (recommended) g++ -O2 -static -pthread -o matching_engine main.cpp file matching_engine # should say: ELF 64-bit LSB executable, x86-64 # On macOS (cross-compile to Linux) x86_64-linux-musl-g++ -O2 -static -pthread -o matching_engine main.cpp
Verify before uploading
file matching_engine # Expected: ELF 64-bit LSB executable, x86-64, statically linked
Add Linux target (once)
rustup target add x86_64-unknown-linux-musl # macOS also needs the linker: brew install filosottile/musl-cross/musl-cross # Then add to ~/.cargo/config.toml: # [target.x86_64-unknown-linux-musl] # linker = "x86_64-linux-musl-gcc"
Compile
cargo build --release --target x86_64-unknown-linux-musl # Binary is at: ./target/x86_64-unknown-linux-musl/release/matching_engine
Verify
file ./target/x86_64-unknown-linux-musl/release/matching_engine # Expected: ELF 64-bit LSB executable, x86-64, statically linked
Compile — Go cross-compiles natively, no extra tools needed
# Works from macOS, Windows, or Linux GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o matching_engine . # Verify file matching_engine # Expected: ELF 64-bit LSB executable, x86-64, statically linked
Tip — make sure your server listens on port 8080
http.ListenAndServe(":8080", nil)
③ Submit — 4 steps
1. Register or log in above 2. Enter a contestant ID (or leave blank to use your username) 3. Pick a test mode — Blitz for quick iteration, Standard for scoring, Marathon for full stress 4. Select your compiled binary and click "Run Stress Test" The platform will: → Containerise your binary in an isolated sandbox → Spawn a bot fleet and hammer your endpoints → Stream live wave-by-wave progress below the upload button → Post your final score to the leaderboard automatically
Common mistakes: forgetting -static (binary links against system libc that doesn't exist in the container) · listening on the wrong port (must be 8080, not 3000 or 8000) · not handling concurrent requests (the bot fleet sends hundreds simultaneously — use goroutines / threads) · crashing on zero-qty or zero-price orders (the chaos wave sends these deliberately — reject them gracefully with a 4xx, don't panic).
